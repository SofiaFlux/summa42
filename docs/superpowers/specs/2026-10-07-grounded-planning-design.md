# Grounded issue planning and independent plan review

Owner authorized continued implementation on 2026-10-07. Use the existing manually invoked GitHub planning recipe; this slice is not the autonomous implementation/PR loop.

`internal/repoworkspace` reads only an explicitly configured local Git repository at a full 40-character commit SHA. Git runs without inherited credentials/configuration, hooks, replace refs or interactive prompts. Source projections select exact regular tracked UTF-8 files (maximum 32 files, 256 KiB total); reject traversal, symlinks, submodules, missing files and oversized input. A checkout creates a fresh detached repository at that SHA without source hooks or shared writable objects. No test or repository command is executed while preparing context.

Git 2.45 or newer must support `--no-lazy-fetch`; older versions fail closed. Missing partial-clone objects are errors, never automatic fetches. Capture and checkout allow no transport; only the explicit local clone step allows `file`. The per-process protocol allowlist cannot be widened by repository-local config. Local Git metadata is still parsed; this preparation primitive is not a process sandbox.

Planning v1 stays readable and remains the default when no grounding was configured. Optional v2 planning persists a canonical, SHA256-bound source projection containing repository identity, commit and selected file contents. An owner-supplied contract contains exact allowed paths (existing or new) and validation commands as argument arrays. The model writes only summary/steps and cannot expand this contract. Commands are inert data in this slice.

The independent plan reviewer loads the plan from the assessment that created the current `github.issue.plan.review` work, verifies its case/issue/revision and triage citations, canonical projection hash and scope contract, then sends the plan plus original issue and code context to a separate model invocation. Its strict output is ACCEPT, REVISE or BLOCK plus a bounded reason. Only v2 plans can receive an implementation handoff. V1 needs re-planning; malformed citations or unavailable models leave the work unchanged.

A review record cites exact plan/context evidence and current work ID. ACCEPT proposes `github.issue.implement` requiring `workspace.repo.write` and `workspace.test`; the existing CaseGrant and latest-revision transaction guard decide whether continuation is authorized. REVISE/BLOCK hold the case for an operator; there is no unbounded repair loop. The reviewer does not grant capabilities, materialize/execute implementation tasks, run commands, push Git or create PRs. Repeated successful ticks cannot repeat the paid review because the work kind has changed or the case has been held.

Review claims use the existing durable Task/Attempt mechanism: one review Task per Work ID, five-minute fenced lease and four-minute model timeout. Concurrent invocations return Busy without paying again. The binding verifier checks exact plan/context/work/task/attempt citations, accepts only the completed manifest, and resumes after a crash before case assessment without another model invocation. Expired attempts cannot advance work; normal runtime wake processing recovers expired leases. Binding acceptance proves that review evidence is correctly recorded, not that implementation tests have passed.

CLI: `run-gh-plan` gains all-or-none `--source-repo`, `--source-repository`, `--source-sha`, repeatable `--context-file`, repeatable `--allowed-path` and `--validation-command-json` (JSON argv). `run-gh-plan-review` takes mission and existing model flags, allowing a separately configured review provider. Native model calls retain their existing UNENFORCED status and direct recipe invocation; leased/governed model usage and monetary settlement remain separate foundation work.

Tests cover real Git pinning despite dirty files/changed HEAD, traversal/symlink rejection, checkout isolation, bounded projections, v1 compatibility, v2 citations, wrong repository/source/evidence, read-only grant blocking, authorized continuation, revision registration during review and strict review parsing. Final Astra review covers the whole PR.
